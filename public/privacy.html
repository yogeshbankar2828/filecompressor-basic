Privacy policy

Last updated: 17 September 2026

What we collect

When you compress files we store, for the life of the job:

  • Original file names, MIME types, and byte sizes
  • Compression mode, status, output name, and output size
  • Job id and expiry time

File contents sit on disk only while the job runs, then as a single output file until expiry. We do not read file contents for advertising or training.

MongoDB

If the operator sets MONGODB_URI, job metadata is written to that database. If the URI is empty, metadata stays in server memory and is lost on restart. File bytes are never stored as MongoDB documents.

Logs and network data

The host and reverse proxy may keep standard access logs (IP address, user agent, path, time). We do not sell this data.

Cookies

This site does not set tracking cookies. The compressor talks to the API with ordinary HTTP requests.

Retention

Jobs expire after the configured TTL (default 60 minutes). Expired output files are deleted. MongoDB records may also expire through a TTL index on expiresAt.

Sharing

We do not share uploads with third parties except the hosting provider and the MongoDB cluster the operator configured. Anyone with the job id can download the output until it expires, so do not post job URLs publicly.

Your choices

Do not upload files you do not want processed on this server. After expiry there is nothing left to delete on request, other than residual server logs held by the host.

Operator

The privacy contact is the person who runs the instance and the custom domain pointed at it.
